# 🚀 راهنمای مدیریت و نسخه‌بندی ورک‌فلوهای n8n با Git

این راهنما برای مدیریت، نسخه‌بندی (Version Control) و پشتیبان‌گیری خودکار ورک‌فلوهای **n8n** در گیت تهیه شده است.

---

## 📁 ساختار پروژه

```text
n8n/
├── compose.yml              # کانفیگ سرویس‌های داکر (n8n, runners, searxng)
├── searxng-settings.yml     # تنظیمات موتور جستجوی SearXNG
├── .env                     # [محرمانه] توکن‌ها و پسوردها (هرگز در گیت قرار نمی‌گیرد)
├── .env.example             # نمونه متغیرها بدون اطلاعات حساس (برای گیت)
├── .gitignore               # لیست فایل‌های نادیده گرفته‌شده توسط گیت
├── sync.sh                  # اسکریپت ساده برای سینک خودکار بین داکر و گیت
├── scripts/
│   └── sync_workflows.py    # موتور پایتون برای تبدیل و تفکیک ورک‌فلوها
└── workflows/               # پوشه فایل‌های JSON هر ورک‌فلو
    ├── Blog Agent.json
    ├── Schema Agent.json
    ├── Find internal linking opportunities using SerAPI and Google Sheets.json
    └── README.md            # جدول مشخصات و وضعیت ورک‌فلوها
```

---

## ⚡ نحوه استفاده سریع (دستورات کاربردی)

اسکریپت `sync.sh` تمام کارهای استخراج، نام‌گذاری تمیز، قالب‌بندی و کامیت را در ۲ ثانیه انجام می‌دهد:

### ۱. ذخیره و کامیت کردن تغییرات در گیت (پرکاربردترین دستور)
هر زمان در پنل مرورگر n8n ورک‌فلوها را تغییر دادید، کافیست در ترمینال بنویسید:
```bash
./sync.sh "توضیح تغییرات شما"
```
> **چه اتفاقی می‌افتد؟** ورک‌فلوها از داکر استخراج می‌شوند، فایل‌های داخل پوشه `workflows/` آپدیت می‌شوند و گیت یک کامیت جدید با پیام شما ثبت می‌کند. اگر ریپازیتوری گیت‌هاب متصل باشد، خودکار `git push` هم می‌شود.

### ۲. فقط استخراج ورک‌فلوها (بدون کامیت)
```bash
./sync.sh export
```

### ۳. مشاهده لیست ورک‌فلوهای موجود در داکر
```bash
./sync.sh list
```

### ۴. بازیابی / بارگذاری ورک‌فلوها در n8n (مسیر برعکس یا Import)
اگر فایلی را در VS Code تغییر دادید، یا پروژه را از گیت روی سیستم دیگری کلون کردید:
```bash
./sync.sh import
```
> تمام فایل‌های JSON پوشه `workflows/` به داخل n8n بازگردانده می‌شوند.

## 🌐 نحوه اتصال این پوشه به گیت‌هاب (GitHub)

برای اینکه پروژه را روی اکانت گیت‌هاب خودتان ذخیره کنید:

1. وارد [GitHub](https://github.com) شوید و یک **New Repository** خالی (بدون README و .gitignore) بسازید.
2. در ترمینال همین پوشه، این دو دستور را اجرا کنید (آدرس ریپازیتوری خود را جایگزین کنید):
```bash
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```
از این به بعد، هر بار دستور `./sync.sh "پیام"` را بزنید، مستقیماً به گیت‌هاب شما هم ارسال خواهد شد.

## 🔒 امنیت و اطلاعات محرمانه (بسیار مهم)

- فایل `.env` حاوی کلیدها و توکن‌های محرمانه سیستم شماست و در فایل `.gitignore` قفل شده تا هرگز روی گیت آپلود نشود.
- اگر پروژه را روی سیستم دیگری کلون کردید، فایل `.env.example` را کپی کرده و به `.env` تغییر نام دهید و مقادیر لازم را پر کنید:
  ```bash
  cp .env.example .env
  ```
- خروجی ورک‌فلوهای n8n به صورت پیش‌فرض شامل رمزها یا API Keyهای تعریف‌شده در بخش Credentials **نیست**، بنابراین فایل‌های درون پوشه `workflows/` برای قرار گرفتن روی گیت امن هستند.

## 🛠️ راه‌اندازی پروژه روی یک سیستم یا سرور جدید

اگر در آینده خواستید این ستاپ را روی سیستم دیگری بالا بیاورید:
```bash
# ۱. کلون کردن ریپازیتوری
git clone <آدرس-ریپازیتوری-شما>
cd n8n

# ۲. ایجاد فایل تنظیمات محیطی
cp .env.example .env

# ۳. اجرای کانتینرهای داکر
docker compose up -d

# ۴. ایمپورت کردن تمام ورک‌فلوها به n8n
./sync.sh import
```
تمام ورک‌فلوهای شما بدون کم و کاست آماده استفاده خواهند بود!
